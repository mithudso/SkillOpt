## 1. What the tools are

- SkillOpt treats a Markdown skill document as the trainable state of a frozen target model; a separate optimizer model turns scored rollouts into bounded add/delete/replace edits; a candidate is accepted only if it strictly beats the current held-out selection score. (README.md:32-41, skillopt/evaluation/gate.py:200-217)
- Two separate entry points. Research engine: package `skillopt`, commands `skillopt-train`, `skillopt-eval`. SkillOpt-Sleep: package `skillopt_sleep`, command `skillopt-sleep`. They have different configs and safety boundaries. (docs/index.md:21-30, pyproject.toml:66-69)
- The deployed artifact is one Markdown file, `best_skill.md`, used unchanged by the target model; no extra inference-time model calls. (README.md:39-42)
- Requires Python >= 3.10. Core deps: openai, pyyaml, numpy, openpyxl, azure-identity, azure-core, httpx. (pyproject.toml:11, pyproject.toml:26-34)
- Choose by goal: to measure before/after test accuracy of a skill against a task set you author, use the research engine with an env (section 8). To improve a skill from your own agent usage with human review of staged proposals, use Sleep (section 9). (docs/index.md:23-26)
- Difference in edit scope: the research engine edits the whole document with literal-string patches; Sleep only writes bullets inside a `<!-- SKILLOPT-SLEEP:LEARNED START -->` ... `<!-- SKILLOPT-SLEEP:LEARNED END -->` block and never touches text outside it. (skillopt/optimizer/skill.py:98-142, skillopt_sleep/memory.py:15-20)

## 2. Install

- PyPI: `python -m pip install skillopt` installs `skillopt-train`, `skillopt-eval`, `skillopt-sleep`. The wheel omits benchmark configs, data materializers, plugin shells/MCP servers and tests; use a source checkout for them. (docs/guide/installation.md:12-24)
- Source: `git clone https://github.com/microsoft/SkillOpt.git && cd SkillOpt && python -m pip install -e .`. (docs/guide/installation.md:35-41)
- Features newer than PyPI 0.2.0 need a source install of main: generic `openai_compatible` research backend, Sleep handoff, Sleep non-Azure compatible endpoints, `--preferences`, Cursor/Pi sources and backends, multi-skill fan-out, reviewed subset adoption. (docs/guide/installation.md:26-33)
- Extras: `alfworld`, `claude` (claude-agent-sdk, json_repair), `qwen` (vllm, json_repair), `searchqa` (datasets), `docs`, `webui` (gradio>=5.50.0,<7), `dev` (ruff, pytest), `all` (alfworld+claude deps only). (pyproject.toml:36-64)
- The `claude` extra does not install the `claude` executable; the `claude_chat` backend runs `claude -p`, so install and log in to Claude Code separately. (docs/guide/installation.md:62-65)
- `.env` is never auto-loaded: `cp .env.example .env`, edit, then `set -a; source .env; set +a`. (docs/guide/installation.md:112-126)
- Verify: `python -c "import skillopt; print('SkillOpt ready!')"`, `skillopt-train --help`, `skillopt-eval --help`, `skillopt-sleep --help`. (docs/guide/installation.md:177-182)

## 4. Backends: names, roles, selection

- Optimizer backends allowed: `openai_chat`, `claude_chat`, `qwen_chat`, `minimax_chat`, `openai_compatible`, `copilot_chat`, `codex_exec`, `claude_code_exec`. Target backends allowed: those plus `cursor_exec`, `copilot_exec`. Anything else raises "Unsupported optimizer/target backend". (skillopt/model/backend_config.py:139-170)
- Exec backends (`codex_exec`, `claude_code_exec`, `cursor_exec`, `copilot_exec`) run an agent CLI in a workspace as the target; env rollout code must support them through `run_target_exec`. Chat backends work with `chat_target(system=..., user=...)` unchanged. (skillopt/model/backend_config.py:181-182, skillopt/model/codex_harness.py:1977-2000)
- Default model per backend: `openai_chat`/`azure_openai` `gpt-4o`; `claude_chat`/`claude_code_exec` `claude-sonnet-4-6`; `cursor_exec` `composer-2.5`; `qwen_chat` `Qwen/Qwen3.5-4B`; `minimax_chat` `MiniMax-M3`; `openai_compatible` `gpt-4o-mini`. (skillopt/model/common.py:18-34)
- `--backend X` fills a role only if it is still at the shipped `openai_chat` default: `claude` -> claude_chat both (default models `claude-sonnet-4-6` unless `--optimizer_model`/`--target_model`; checked offline); `codex` -> codex_exec both; `copilot_chat`, `openai_compatible` -> both; `claude_code_exec`, `cursor_exec`, `copilot_exec`, `qwen_chat`, `minimax_chat` -> optimizer `openai_chat`, target that backend. Aliases: `claude`/`anthropic`, `cursor`, `copilot`, `qwen`, `minimax`, `compat` map to `claude_chat`, `cursor_exec`, `copilot_chat`, `qwen_chat`, `minimax_chat`, `openai_compatible`. (scripts/train.py:641-712, skillopt/model/common.py:36-64)
- Claude-subscription run with no API key: `--backend claude` (both roles go through `claude -p`; the skill reaches the target as a system-prompt file via `--append-system-prompt-file`). (scripts/train.py:652-654, skillopt/model/claude_backend.py:254-269)
- `--target_backend claude_code_exec` makes the target a real Claude Code agent with the skill written to `.agents/skills/skillopt-target/SKILL.md` in its workspace, but only for envs whose rollout calls `run_target_exec` (built-ins such as searchqa); `chat_target` raises `NotImplementedError` on an exec target, so chat-only envs such as `skilltask` need a chat target backend. (skillopt/model/codex_harness.py:109-111, skillopt/envs/searchqa/rollout.py:136-146)
- `copilot_chat` does not support caller-supplied tools or structured tool calls, so environments that need them must use another chat backend; `claude_chat` emulates tool calls through a prompt-level compatibility shim. (docs/guide/configuration.md:59-60, skillopt/model/claude_backend.py:123-128)
- Any OpenAI Chat Completions provider (DeepSeek, Groq, Together, Ollama `http://localhost:11434/v1`, vLLM `http://localhost:8000/v1`, LiteLLM, OpenRouter): `--cfg-options model.optimizer_backend=openai_compatible model.target_backend=openai_compatible model.optimizer=<id> model.target=<id>` plus `OPENAI_COMPATIBLE_*` env. (docs/guide/new-backend.md:20-31, docs/guide/new-backend.md:83-92)

## 6. Configuration

- YAML with `_base_` inheritance. `_base_` is a single string path resolved relative to the child file; a list is not supported; circular inheritance raises. Child values win over base, including when the two use flat vs structured spellings. (skillopt/config.py:245-272, docs/guide/new-benchmark.md:370-373)
- Sections: `model`, `train`, `gradient`, `optimizer`, `evaluation`, `env`; a config with any of these dict sections is "structured" and is flattened to a flat dict for the trainer. Extra `env.*` keys pass through to the adapter constructor by name. (skillopt/config.py:25-27, skillopt/config.py:287-324)
- The adapter receives only the flat-config keys that match its `__init__` parameter names. Flat names: `train.seed`->`seed`, `optimizer.learning_rate`->`edit_budget`, `gradient.*`->`minibatch_size`, `analyst_workers`, `failure_only`, `env.*`->same name. (scripts/train.py:116-125, skillopt/config.py:126-161)
- A config without `_base_` lacks required keys (`batch_size`, `num_epochs`, `merge_batch_size`, `eval_test`, ...); inherit `configs/_base_/default.yaml`. From a PyPI install the shipped configs are absent: copy `configs/_base_/default.yaml` and point `_base_` at the copy (absolute paths work). (skillopt/engine/trainer.py:868-872, docs/guide/installation.md:21-24)

Defaults from `configs/_base_/default.yaml` (meaning in parentheses):

## 7. The loop and the skill document

- Per step: rollout (target runs a batch of train items with the current skill) -> reflect (optimizer analyses minibatches into edit patches; failures always, successes unless `failure_only`) -> aggregate (merge similar patches) -> select (cap at the LR edit budget) -> update (apply) -> gate (selection-split rollout; accept only if score strictly higher). (docs/guide/training-loop.md:11-24, docs/guide/training-loop.md:40-44)
- Before training the initial skill is scored on the selection split; a candidate must strictly exceed the current score (`cand_score > current_score`), so an initial skill already at the metric ceiling cannot be improved. (skillopt/engine/trainer.py:1096-1123, skillopt/evaluation/gate.py:200-217)
- Gate results: `accept_new_best`, `accept`, `reject` (`force_accept` when the gate is off); no usable patches gives `skip_no_patches`. Total steps = `num_epochs * ceil(train_size / (batch_size * accumulation))`; `cosine` and `linear` decay the edit budget from `learning_rate` to `min_learning_rate`. (skillopt/evaluation/gate.py:30, skillopt/engine/trainer.py:892-894)
- Epoch boundary: slow update (longitudinal comparison of previous vs current epoch skill, written into the protected `SLOW_UPDATE` block, from epoch 2; epoch 1 injects an empty placeholder) and meta-skill memory (epoch 2+). (skillopt/engine/trainer.py:1751-1777, docs/guide/training-loop.md:84-100)
- Edits are literal-string operations on the document: `append`, `insert_after` (falls back to append if the target is absent), `replace` and `delete` (skipped if the target text is not found); edits that target text inside a protected region are skipped. (skillopt/types.py:23, skillopt/optimizer/skill.py:94-145)
- Protected machine-managed regions: `<!-- SLOW_UPDATE_START -->...<!-- SLOW_UPDATE_END -->` and `<!-- APPENDIX_START -->...<!-- APPENDIX_END -->`; keep the markers when copying a trained skill. Appends land before the first protected region. (docs/guide/skill-document.md:45-59, skillopt/optimizer/skill.py:98-106)
- `env.skill_init` points at the starting Markdown (empty file = blank start). It must be a real file path: the shipped base value `""` resolves to the working directory and crashes with `IsADirectoryError`; a nonexistent path silently starts blank, so a typo is not detected. (skillopt/engine/trainer.py:858-865, docs/guide/skill-document.md:76-78)
- Rollout result contract: each dict needs `id` (str), `hard` (0/1 or float 0..1), `soft` (float 0..1); extra keys are kept. Scores are averaged by `compute_score`. (skillopt/envs/base.py:216-232, skillopt/types.py:104-124)

## 9. Recipe B: SkillOpt-Sleep for a Claude Code skill

1. Install `pip install skillopt` (or source). Real backend `claude` needs the `claude` CLI on PATH and logged in. Default backend is `mock` (no provider calls, nothing meaningful learned). (docs/sleep/README.md:148-157, plugins/claude-code/README.md:84-87)
2. Preview without staging: `skillopt-sleep dry-run --project "$(pwd)" --backend claude --progress`. A real-backend dry run still spends tokens. (docs/reference/cli.md:195-198, docs/reference/cli.md:386-388)
3. Stage a proposal: `skillopt-sleep run --project "$(pwd)" --backend claude --target-skill-path path/to/SKILL.md`. `--project` only scopes transcripts/state/staging; pass `--target-skill-path` to name the skill document. Default target is `~/.claude/skills/skillopt-sleep-learned/SKILL.md`. (docs/sleep/openai-compatible-endpoints.md:114-117, skillopt_sleep/config.py:182-192)
4. Skip transcripts with a reviewed task file: `skillopt-sleep run --project "$(pwd)" --backend claude --tasks-file tasks.json --target-skill-path SKILL.md`. Real backends refuse a file whose top-level `"reviewed"` is not `true` (exit 2). (skillopt_sleep/__main__.py:246-252)
5. Task file: `{"format":"skillopt_sleep.tasks.v1","project":".","reviewed":true,"tasks":[...]}` or a bare JSON array. Task fields: `id`, `project`, `intent` (the prompt), `context_excerpt`, `system`, `reference_kind` (`exact`|`rubric`|`rule`|`none`), `reference` (answer or rubric text), `judge` (`{"kind":"rule","checks":[{"op","arg","description"}]}`), `split` (`train`|`val`|`test`), `origin` (`real`), `tags`, `skill_hint`. Verified run with the mock backend: 6 tasks, staging dir created. (skillopt_sleep/tasks_file.py:22-30, skillopt_sleep/types.py:48-86)
6. If no task has `split` val/test and there are >= 2 tasks, splits are assigned automatically (`holdout_fraction` 0.34). Prefer explicit `val` tasks: the gate scores them. (skillopt_sleep/tasks_file.py:44-54)
7. Rule-judge ops: `section_present`, `section_contains`, `regex`, `max_chars`, `min_chars`, `contains`, `not_contains`, `no_refusal`, `tool_called`. A task passes (`hard=1`) only if all checks pass; `soft` = fraction passed. Format-only (shape) judges can be gamed by reformatting; prefer `rubric`/outcome checks. Invalid regexes are rejected at load. (skillopt_sleep/judges.py:144-153, skillopt_sleep/judges.py:194-250)
8. Review `<project>/.skillopt-sleep/staging/<YYYYMMDD-HHMMSS>/report.md` (baseline -> candidate held-out score, gate action, edits) and `proposed_SKILL.md`. Then `skillopt-sleep status --project "$(pwd)"` and `skillopt-sleep adopt --project "$(pwd)" --legacy`. Adoption backs the live file up first; nothing is applied without `adopt` or `--auto-adopt`. (skillopt_sleep/staging.py:824-829, plugins/claude-code/README.md:30-31)
9. Claude Code plugin: `/plugin marketplace add ./plugins/claude-code` then `/plugin install skillopt-sleep@skillopt-sleep`; use `/skillopt-sleep dry-run|run|status|adopt|harvest|schedule|unschedule`. `/skillopt-sleep-handoff run` lets the current session answer model calls through prompt/answer files (no `claude -p`, no API key; answer each prompt in a fresh context). (plugins/claude-code/README.md:38-49, plugins/claude-code/README.md:99-117)
10. The `claude` Sleep backend runs `claude -p --output-format text --disable-slash-commands --disallowedTools '*'` in an empty temp dir, reads the model from `--model` or `SKILLOPT_SLEEP_CLAUDE_MODEL` (default `sonnet`), and logs "Not logged in" auth errors. (skillopt_sleep/backend.py:709, skillopt_sleep/backend.py:722-728)
11. Schedule: `skillopt-sleep schedule --project "$(pwd)" --backend claude --hour 3 --minute 17` (default 03:17); `unschedule` (`--all` removes every managed entry). The scheduler keeps only project, backend, time and `--auto-adopt`; put `transcript_source`, `model`, `target_skill_path` etc. in `~/.skillopt-sleep/config.json` first. (skillopt_sleep/__main__.py:878-884, docs/reference/cli.md:421-428)

(skillopt_sleep/__main__.py:97-149)
- `adopt` adds `--staging DIR`, `--skill NAME` (repeatable), `--all-skills`, `--legacy`; bare adopt on a fan-out night promotes nothing. `harvest` adds `--output FILE`. `evalkit` takes `--manifest --a --b|--aa --alpha --boot --seed --allow-graded --json`. (skillopt_sleep/config.py:26-93)

- Multi-skill fan-out: `"multi_skill_fanout": true` stages one `proposed_SKILL.<name>.md` per hinted skill (resolved from `.agents/skills`, `.claude/skills`, `.cursor/skills`, `.devin/skills`); `auto_adopt` never promotes them. (docs/sleep/README.md:347-378, docs/sleep/multi-skill-staging.md:15-17)

## 13. Common errors and fixes

- `ValueError: Unknown environment 'X'. Available: [...]`: env not registered in `scripts/train.py` / `scripts/eval_only.py` (or launcher). (scripts/train.py:109-113, docs/guide/new-benchmark.md:385-386)
- `TypeError: Can't instantiate abstract class ...Adapter`: implement `build_train_env`, `build_eval_env`, `rollout`, `get_task_types`. (docs/guide/new-benchmark.md:388-390)
- `IsADirectoryError` at start: `env.skill_init` is `""`; set a real file path. (skillopt/engine/trainer.py:858-861)
- `Configured train_size=N does not match loaded train split size=M`: set `train.train_size: 0` or fix the split. (skillopt/engine/trainer.py:437-441)
- `merge_batch_size must be >= 2` / `batch_size must be positive`: fix `gradient.merge_batch_size` / `train.batch_size`. (skillopt/engine/trainer.py:884-889)
- Every step logs `skip_no_patches`: rollouts lack `predictions/<id>/conversation.json` (or ids differ), or the analyst returned no usable JSON; json_repair (extras `claude`/`qwen`) helps non-OpenAI backends. (docs/guide/new-benchmark.md:401-403, requirements.txt:20-24)
- All candidates rejected / no gain: selection split too small or initial skill at ceiling; use `gate_metric: soft|mixed`, enlarge val, or raise `optimizer.learning_rate`. (configs/features/soft_gate.yaml:16-21, skillopt/evaluation/gate.py:200-217)
- `NotImplementedError: chat_target is only supported with target_backend=openai_chat, claude_chat, ...`: the target is an exec backend but the env rollout only calls `chat_target`; pick a chat target. (skillopt/model/__init__.py:267-271)
- `Azure OpenAI endpoint is not configured for optimizer`: set `AZURE_OPENAI_ENDPOINT` (or the `OPTIMIZER_`/`TARGET_` variant). (skillopt/model/azure_openai.py:286-293)
- `404 Resource not found` against a non-Azure server (Sleep or research): use `AZURE_OPENAI_AUTH_MODE=openai_compatible` or the `openai_compatible` backend. (docs/sleep/openai-compatible-endpoints.md:29-37)
- `Unsupported optimizer backend: 'cursor_exec'`: `cursor_exec` and `copilot_exec` are target-only. (skillopt/model/backend_config.py:139-152)
- `[sleep] refusing real-backend replay from an unreviewed tasks file`: set `"reviewed": true` after inspecting the file. (skillopt_sleep/__main__.py:246-252)
